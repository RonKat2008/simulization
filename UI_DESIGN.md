# Simulization interface clarity contract

Purpose: help first-time observers understand a six-round merchant experiment and inspect its evidence. Primary action: select information visibility, start one run, inspect a recent action and its observer-only truth, then open that run's persisted report.

Direction: readable, restrained research interface around the existing expressive pixel village. System sans typography for explanations/data; existing palette/components retained. No new libraries or external design services. Reference observations from the running app: uppercase LABELLED/BLIND controls and seed dominated launch; metric grid pushed village below fold; raw log showed hundreds of events; 'private plan' implied hidden internal cognition; single-run report led with an unavailable comparison.

Hierarchy: launch objective and plain information controls, advanced seed/pair; run current phase and village, eight recent meaningful actions, optional full log/metrics; selected agent public record, observation policy and observer truth; report actual behavior counts before comparisons, scores separate from behavior and cautious hierarchy wording.

Target viewports: 1440x900, 430x932. Parent owns actual screenshot evidence and keyboard/reduced-motion verification; source inspection is not visual proof.

States: loading = existing connection/init progress; empty = no actions/no report yet plus navigation; error = explicit launch/connection/report failure, no silent fixtures; partial = current events plus pending report status; success = completed cursor and persisted-report link; permission = no app permission/auth screen (local configured server); new paid runs remain separately authorized in this session.

Implementation: plain radio labels; explicit live vs server-side stub rehearsal notice; advanced controls disclosure; reduced CSS and Phaser motion; roster-based company colors for neutral merchant IDs; canvas accepts only contiguous sequence and exposes runId/acceptedSeq data attributes for verification; no agent-private data in those attributes.

Known limits: inspector explains permitted observations, not a full captured private input. Plans are self-reported model outputs. Scripted replays remain explicitly labeled. One run cannot establish provider bias, unethical behavior or leadership.
